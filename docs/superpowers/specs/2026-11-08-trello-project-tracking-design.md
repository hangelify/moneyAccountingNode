# Трекинг проекта (Trello → Linear) — design

## Цель
Одна Trello-доска на весь продукт (Сервер `moneyAccountingNode` + Фронт
`moneyAccountingReact`), которая служит живой документацией работы: что в
бэклоге, что в работе, что вошло в какой релиз, где спека и PR каждой задачи.
Доску ведёт Claude автоматически по ходу работы; пользователь приоритизирует.

Успех: за минуту по доске видно, что сейчас в работе, что войдёт в следующий
релиз каждого репозитория, что ушло в прошлые релизы, и по любой карточке
можно дойти до спеки, ветки и PR (и обратно — от кода к карточке).

## Решения (согласованы с пользователем)
- Пользователи доски: только владелец проекта и Claude. Поэтому лёгкий
  Kanban: без исполнителей, WIP-лимитов, спринтов и story points.
- Ведение доски — автоматически, Claude (правила ниже). Приоритизация и
  релизы — за пользователем.
- Раздельные версии Сервера и Фронта (свой SemVer, свои теги, свои релизы).
- Одна доска, списки по статусу, версия — в Custom Field (вариант A).
- ID карточки входит в имя ветки и описание PR.

Отклонено:
- Общая версия продукта: пользователь хочет выпускать репозитории независимо.
- Две доски (Server / Front): парная фича (эндпоинт + экран) жила бы на двух
  досках, двойная работа для одного человека.
- Списки по релизам, статус в метках (как Jira Versions): не видно, что в
  работе сейчас, статус в метках неудобно менять.
- Метки приоритета P2/P3: для одного человека приоритет = позиция в списке.
- Отдельные карточки на каждый исторический PR (#58–#86): шум; история
  v0.1.0 хранится одной карточкой-релизом.

## Соответствие Jira → Trello
| Jira | Trello |
|---|---|
| Epic | метка `epic:<имя>` + ссылка на спеку |
| Story / Bug / Task / Tech debt | метка типа |
| Component | метки `server` / `front` |
| Fix Version | Custom Fields `Fix version server` / `Fix version front` |
| Backlog / Sprint | списки Backlog и Next |
| Release notes | карточка-релиз в списке Released |

## Списки (слева направо)
| Список | Содержимое | Кто кладёт |
|---|---|---|
| 📥 Inbox | неразобранные идеи и баги | пользователь / Claude |
| 📋 Backlog | разобранные задачи, верх = важнее | порядок задаёт пользователь |
| 🧱 Tech debt | техдолг | Claude, когда замечает |
| ⏭️ Next | 3–7 задач, которые берём следующими | пользователь выбирает |
| 🔨 In progress | есть ветка | Claude |
| 👀 Review / PR | открыт PR | Claude |
| ✅ Done (unreleased) | смёржено в `dev`, не выпущено | Claude |
| 🚀 Released: server vX.Y.Z | по списку на релиз | Claude при релизе |
| 🚀 Released: front vX.Y.Z | по списку на релиз | Claude при релизе |
| 📌 Docs & Decisions | правила доски, ADR, ссылки на спеки, история версий | Claude |

Списки Released архивируются после 2–3 следующих релизов того же
репозитория; карточка-релиз перед этим копируется в Docs & Decisions.

## Метки
- Компонент: `server` (синяя), `front` (голубая). Парная фича — обе.
- Тип: `feature` (зелёная), `bug` (красная), `tech-debt` (оранжевая),
  `chore` (серая), `security` (чёрная).
- Приоритет: только `P1-urgent` (пурпурная).
- Epic: `epic:<имя>` (жёлтые), заводятся по мере надобности
  (например `epic:households`, `epic:bills-photo`).

## Custom Fields
- `Fix version server` — текст, например `0.2.0`.
- `Fix version front` — текст.
- `Spec` — ссылка/путь на `docs/superpowers/specs/…`.
- `PR` — ссылки на PR (один или оба репозитория).

Fallback, если Custom Fields недоступны на тарифе: версия — метки
`sv0.2.0` / `fv0.2.0`, ссылки — в разделе «Ссылки» описания.

Power-Up: GitHub (показывает привязанные PR, ветки, коммиты и их статус на
карточке). Подключает пользователь.

## Карточка
**Название:** префикс `[S]`, `[F]` или `[S+F]` + действие.
Пример: `[S+F] Конвертация валют в домохозяйстве`.
ID — короткий номер карточки Trello (`#42`).

**Описание:**
```
## Зачем
1–3 предложения: проблема / ценность.

## Что сделать
- …

## Критерии готовности
- [ ] …

## Ссылки
- Spec: docs/superpowers/specs/…
- Plan: docs/superpowers/plans/…
- PR server: …   PR front: …
```
- Баг: вместо «Что сделать» — «Шаги воспроизведения / Ожидаемо / Фактически».
- Техдолг: дополнительно строка «Риск, если не делать».

**Чек-лист «Готово к merge»:** тесты, линт, спека/доки обновлены (для
парных фич — `docs/frontend-*-integration.md`), CI зелёный.
Парная фича, если части сильно расходятся по времени, — два чек-листа
«Server» и «Front».

**Комментарии — журнал событий**, по строке на событие: «Спека написана»,
«Ветка feat/42-…», «PR #87 открыт», «Смёржено в dev (abc1234)».

Парная фича — одна карточка `[S+F]`, не две.

## Связь с git
- Ветка: `<тип>/<id>-<slug>`, например `feat/42-household-currency`.
  Тип как сейчас в репозитории (`feat`, `fix`, `chore`; во фронте `enh`).
- Описание PR содержит строку `Trello: #<id>` и ссылку на карточку.
- Карточка содержит ссылки на ветку и PR (поле `PR`, комментарии, GitHub
  Power-Up).
- Работа без карточки (мелочь в один коммит) допустима; ветка тогда без ID.

## Автоматика Claude
| Событие | Действие на доске |
|---|---|
| Пользователь описал идею/баг или Claude нашёл проблему | карточка в Inbox; если тип и приоритет ясны — в Backlog; техдолг — в Tech debt |
| Начат brainstorming / спека по задаче | найти карточку или создать; в Next; путь спеки в поле `Spec` + комментарий |
| Создана ветка | имя с ID; карточка в In progress; комментарий с веткой |
| Открыт PR | `Trello: #<id>` в описании PR; ссылка в поле `PR`; карточка в Review / PR |
| PR смёржен в `dev` | карточка в Done (unreleased); комментарий с хешем; чек-лист отмечен |
| Найден техдолг/баг вне текущей задачи | отдельная карточка в Tech debt / Inbox со ссылкой на место в коде; в текущую задачу не тянуть |
| Начало сессии с работой над задачей | сверить доску с git: смёрженные PR, чьи карточки не в Done, — передвинуть |

Без явного согласия пользователя Claude не:
- меняет порядок Backlog;
- переводит в Next задачу, которую пользователь не выбрал (кроме случая,
  когда пользователь прямо просит её начать);
- удаляет карточки (только архивирует, и только по просьбе);
- выполняет релиз.

Если Trello недоступен: работа продолжается, Claude перечисляет в конце
хода несделанные изменения доски и применяет их, когда доступ вернётся.

Правила хранятся:
- кратко — в `CLAUDE.md` обоих репозиториев (ID доски и списков, правила
  выше), чтобы каждая сессия работала одинаково;
- полностью — в этой спеке и в карточке «Правила доски» в Docs & Decisions.

## Релиз
Версии: SemVer на репозиторий, пока `0.x`. Minor — есть фичи, patch —
только фиксы. Источник версии — `package.json` + git-тег `vX.Y.Z` в
соответствующем репозитории (без префикса; префикс `server`/`front` — только
в названиях списков и карточек на доске).

Запускается командой пользователя («выпускаем server»):
1. Claude показывает карточки в Done (unreleased) с меткой репозитория и
   предлагает номер версии; пользователь подтверждает состав и номер.
2. Claude поднимает `version` в `package.json`, делает PR `dev → main`
   (squash, как сейчас). После merge и деплоя (Jenkins для сервера) — тег
   `vX.Y.Z` на `main`.
3. Создаётся список `🚀 Released: <repo> vX.Y.Z`, карточки переносятся,
   заполняется поле `Fix version <repo>`.
4. В этом списке — карточка-релиз `<repo> vX.Y.Z — <дата>`: release notes
   по разделам Features / Fixes / Tech debt со ссылками на карточки, PR
   релиза, тег.
5. Карточка `[S+F]` уходит в Released, только когда выпущены обе части; до
   этого она в Done с заполненным полем выпущенной части.

## Предусловия
- Trello-коннектор (`mcp.trello.com`) подключён к сессии Claude.
- У пользователя есть Trello-workspace для доски.

## Проверка
- Доска создана со всеми списками, метками и полями; карточка «Правила
  доски» на месте.
- `CLAUDE.md` в обоих репозиториях содержит ID доски/списков и правила.
- Теги `v0.1.0` есть в обоих репозиториях; карточки-релизы созданы.
- Пробный прогон на одной реальной задаче: карточка проходит
  Next → In progress → Review / PR → Done, ветка и PR содержат ID, в
  карточке есть ссылки и журнал комментариев.

## Linear (заменяет Trello, 2026-11-08)
Trello MCP-коннектор не умеет создавать/переименовывать метки и Custom Fields
(`trelloWriteBoard` принимает только `action: create`), браузерная настройка не
удалась. Пользователь выбрал переезд на Linear: полноценный MCP и GitHub-интеграция,
которая сама связывает ветки/PR с задачами и двигает статусы. Доска Trello
`moneyAccounting` устарела; архивирует пользователь.

Соответствие решениям выше:
| Было (Trello) | Стало (Linear) |
|---|---|
| Доска | Команда `HAN` (Hangelify), workspace `hangelify` |
| Inbox / Backlog | Backlog (неразобранное — без приоритета) |
| Tech debt (список) | метка `tech-debt` + фильтр |
| Next / In progress / Review / Done | Todo / In Progress / In Review / Done |
| Released: <repo> vX.Y.Z | Project `<repo> vX.Y.Z` (Completed) + release notes в описании |
| Docs & Decisions | Documents команды HAN |
| Метки `feature`, `bug`, `P1-urgent` | встроенные `Feature`, `Bug`, поле Priority |
| Custom Fields (Spec, PR, Fix version) | раздел «Ссылки», вложения PR от интеграции, Project |
| `[S+F]` — одна карточка | родительская задача + подзадачи `[S]` и `[F]` (раздельные релизы) |
| Ветка `<тип>/<N>-<slug>` | `<тип>/han-<N>-<slug>`, PR `Fixes HAN-N` |

Всё остальное (автоматика Claude, «без согласия не делать», процесс релиза, SemVer
на репозиторий, теги `vX.Y.Z`) — без изменений. Краткие правила — в `CLAUDE.md` обоих
репозиториев и документе «📌 Правила трекинга проекта».

Перенесено: проекты `server v0.1.0`, `front v0.1.0`; 16 документов; задачи HAN-5…HAN-20
(включая найденную при переносе незавершённую `[S+F] Batch bill photos` — ветки
`feat/batch-bill-photos` локально в обоих репо, не смёржены).

## Идеи и эпики (2026-11-08)
Владелец пишет «Идея: …». Порядок работы Claude:
1. Исследовать: код обоих репо (модели, эндпоинты, экраны), бэклог и спеки в Linear; при необходимости — веб (практики, библиотеки).
2. Задать 1–3 вопроса, без которых нельзя (цель, рамки, «не делаем»).
3. Показать в чате черновик эпика: проблема и ценность; входит / не входит; риски и открытые вопросы;
   задачи `[S]`/`[F]` с описанием, критериями готовности, оценкой, зависимостями; раскладка по релизам.
4. Только после «да» — создать в Linear.
5. При взятии эпика в работу крупные задачи идут через brainstorming → спека → план.

Структура в Linear (Releases/pipelines пока не используются):
- **Эпик** = задача с меткой `epic`, название `Epic: <имя>`, бриф в описании; задачи эпика — её подзадачи.
- **Задача** = подзадача эпика с метками `server`/`front` + тип, в проекте релиза своего репозитория.
- **Будущий релиз** = Project `<repo> vX.Y.Z` в статусе Planned (сейчас: `server v0.2.0` = P-HAN-3,
  `front v0.2.0` = P-HAN-4). Новые — по мере планирования (`v0.3.0`…). Состав релиза утверждает владелец.
- Сам эпик в проект не кладётся (он может охватывать оба репо и несколько релизов).
