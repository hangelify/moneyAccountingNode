# HAN-149 — чеки категории за период (переход из отчёта лимитов)

Linear: [HAN-149](https://linear.app/hangelify/issue/HAN-149) · эпик HAN-21 · отчёт HAN-25 / HAN-29 ·
«Прочие траты» вынесены в HAN-152.

## Зачем

В отчёте лимитов пользователь видит факт категории за период и хочет открыть чеки, из которых он
сложился. Список должен объяснять число из отчёта: чек с несколькими категориями показывается
целиком, но рядом — вклад этой категории, а над списком — итог категории, совпадающий с отчётом.

## Цели

- Клик по категории в строке отчёта (`LimitReportRow`) открывает `/bills/confirmed` с категорией и
  периодом отчёта.
- У каждого чека: сумма чека **и** вклад категории в валюте бюджета.
- Над списком: итог категории за выбранные фильтры; при фильтрах «только период» он равен `spent`
  в отчёте.
- Фильтр категории виден снимаемым чипом и сочетается с остальными фильтрами списка.

## Не цели

- Переход из «Прочих трат» (без категории / без лимита) — HAN-152.
- Выбор категории в панели фильтров (только чип из ссылки).
- Несколько категорий в одном фильтре; подкатегории.

## Анти-цели

- Итог в списке расходится с фактом в отчёте за тот же период (даже на копейку).
- Остальные фильтры перестают работать вместе с категорией.

## Подходы

- **А. Параметр `category_id` в `GET /bills`** — одна точка, но список и так сложный, и итог
  категории туда не ложится.
- **Б. Отдельный эндпоинт `GET /bills/by-category/:categoryId`** — **выбран владельцем.** Чистое
  место для `category_amount` и итога; дублирование снимается общим построителем `WHERE` и маппингом.
- **В. Вклад считает фронт по деталям чеков** — N запросов, своя конвертация, риск расхождения. Отброшен.

## Дизайн — сервер

**Маршрут:** `GET /households/:hid/bills/by-category/:categoryId` в `BillController`, объявлен
**до** `@Get(':id')`. Guard и права — как у `GET /bills`. `categoryId` — UUID (`ParseUUIDPipe`).

**Запрос:** тот же `ListBillsQueryDto` (даты, магазины, валюта, источник, сумма, дубликаты, пагинация).
Проверка `date_from <= date_to` — общая.

**Рефакторинг `BillCrudService.listBills`** (поведение `GET /bills` не меняется):
- вынести сборку `conditions/params` в приватный `listWhere(householdId, filters)`;
- вынести маппинг строки в `BillResponseDto` в общую функцию.

**Новый метод `listBillsByCategory(householdId, categoryId, filters)`:**
- категория ищется среди категорий бюджета **включая архивные** (`deleted_at` не важен); нет — 404.
  Архивные нужны: отчёт показывает их строки с фактом.
- к `WHERE` добавляется
  `EXISTS (SELECT 1 FROM bill_sub_categories WHERE bill_id = b.id AND category_id = ?)`;
- `category_amount` у чека: `ROUND(SUM(l.amount * fx.factor), 2)` по строкам категории (`fx` — тот же
  `householdConversionJoin`, что у `household_amount`); `null`, если курса нет;
- итог по всем страницам (отдельный агрегирующий запрос с тем же `WHERE`), считается **как в
  `fetchSpent`**: округление по группе `(category_id, sub_category_id)`, затем сумма групп — иначе
  возможно расхождение в копейках с отчётом. Строки без курса не входят в сумму и считаются в
  `unconverted_lines`.

**Ответ** (`BillsByCategoryResponseDto`): формат списка (`data`, `meta` — как
`BillListResponseDto`) плюс
- `category: { id, name, archived }` — фронт берёт название для чипа отсюда;
- `category_total: number` — итог в валюте бюджета; `household_currency`;
- `unconverted_lines: number`;
- у каждого элемента `category_amount: number | null` (суммы в API — числа, как `household_amount`).

Swagger: описание эндпоинта и полей, пример.

## Дизайн — фронт

- `ConfirmedBillsFilters.category_id: string | null`; `parseBillsSearchParams` читает `category_id`
  (UUID, иначе `null`); `buildBillsQueryParams` кладёт его (он же строит URL страницы), а
  `billsApi.listByCategory` убирает `category_id` из query — он идёт в путь.
- `useConfirmedBills`: при `category_id` вызывает `bills.listByCategory(hid, id, filters, page, limit)`,
  иначе — как сейчас. Ключ запроса включает `category_id`.
- Список: при категории — чип «Категория: <name> ✕» (снятие убирает `category_id` из URL, остальные
  фильтры остаются), строка итога «В категории <name>: X €» + `UnconvertedNote` при
  `unconverted_lines > 0`, у строк чека подпись «из них <name> X €».
- Чужая/несуществующая категория (404): чип «Категория недоступна ✕», пустой список.
- Отчёт: название категории в `LimitReportRow` — ссылка на
  `/bills/confirmed?category_id=<id>&date_from=<start>&date_to=<end − 1 день>`. Отчёт считает
  `[start, end)`, список — включительно; `include_duplicates` не ставится. Строка итога и «Прочие
  траты» — без ссылки.

## Критерии готовности

- Сервер: int-тесты — фильтр по категории (чек с несколькими категориями попадает целиком,
  `category_amount` = вклад), итог совпадает с `spent` отчёта за период (в т.ч. чек в чужой валюте и
  строка без курса), архивная категория, чужая категория → 404, `GET /bills` не изменился;
  e2e + Swagger.
- Фронт: тесты парсинга/сборки параметров, ссылки из строки отчёта (`end − 1 день`), чипа и его
  снятия, итога и подписи вклада.
