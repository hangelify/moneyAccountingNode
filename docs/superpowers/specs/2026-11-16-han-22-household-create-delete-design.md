# HAN-22 — создание и удаление бюджета: сид категорий, лимит, защита последнего, своё имя

Linear: [HAN-22](https://linear.app/hangelify/issue/HAN-22) · эпик HAN-21 · фронт HAN-26 зависит от этой задачи ·
копия общего бюджета при удалении вынесена в [HAN-145](https://linear.app/hangelify/issue/HAN-145).
Размер: небольшая задача (~3 пункта; было 2, выросла из-за своего имени и лимита).

## Зачем

Пользователь создаёт дополнительные бюджеты («Семья», «Отпуск», «Ремонт») и сразу ими пользуется. Сейчас
`POST /households` создаёт пустой бюджет без категорий, удалить можно даже последний, а фронту (HAN-26) нечем
предупредить «в бюджете N чеков». Участник общего бюджета хочет видеть его под своим удобным именем.

## Что уже есть (на origin/dev, 3ed7c1f)

- `HouseholdService.createHousehold` создаёт бюджет и owner без категорий. Валюта — переданная или пользователя.
- Регистрация (`auth.service.ts`) создаёт пользователя, бюджет «Personal» и owner в транзакции, а
  `CategoryDefaultsService.seedForHousehold` вызывает **после** неё, ошибку только логирует.
- `seedForHousehold` открывает свою транзакцию на `em.fork()` и берёт `pg_advisory_xact_lock(hashtext(householdId))`.
- `softDeleteHousehold` ставит `deleted_at` без проверок; owner проверяется в контроллере (`assertOwner`, 403).
- `listHouseholds` populate'ит `household.members`, сортировки нет.
- Лимит приглашений — `HOUSEHOLD_MAX_ACTIVE_INVITES` (`household-invites.env.ts`, DI-токен, проверка в транзакции
  под `PESSIMISTIC_WRITE` на бюджет).
- Данные удалённого бюджета: `DraftCleanupService` удаляет старые черновики/failed во **всех** бюджетах (фильтра по
  бюджету нет); из S3 код ничего не удаляет нигде; pending `ai_requests` дорабатывают и пишут в удалённый бюджет —
  его никто не читает (`findHouseholdRole` отсекает `deleted_at`).

## Решения владельца (2026-11-15)

1. Удаление общего бюджета: каждый участник получает копию как личный бюджет. **Вынесено в HAN-145.** До неё
   удаление бюджета, где есть кто-то кроме owner, → 409.
2. У пользователя всегда есть бюджет после регистрации.
3. Лимит — **5 бюджетов** на пользователя, считаются и свои, и те, куда пригласили.
4. Имя бюджета не уникально. Создатель задаёт основное имя; участник может задать себе своё.

## Цели / не цели / анти-цели

**Цели:** новый бюджет сразу с категориями по умолчанию; не больше 5 бюджетов на пользователя; нельзя удалить
последний бюджет и бюджет с другими участниками; своё имя бюджета у каждого участника; `bill_count` и
`member_count` в списке одним запросом.

**Не цели:** копия общего бюджета при удалении (HAN-145); каталог направлений вместо сида (HAN-58); поле
`is_default`; восстановление удалённого бюджета; чистка S3.

**Анти-цели:** пользователь без бюджета или бюджет без категорий; гонка, при которой два параллельных запроса
обходят лимит или удаляют оба последних бюджета; N+1 в списке (не усугублять HAN-11).

## Подходы

- **Своё имя — колонка `household_members.display_name` (выбрано).** Имя принадлежит паре «пользователь–бюджет»,
  строка участника уже есть, удаляется вместе с членством.
- Отдельная таблица `household_aliases` — лишняя сущность ради одной строки.
- Поле в профиле пользователя (jsonb с именами по бюджетам) — оторвано от членства, не чистится при выходе.

Остальное (сид, лимит, удаление, счётчики) делается одним очевидным способом — по образцу существующего кода.

## Дизайн

### Сид в транзакции

- `seedForHousehold(householdId, em?)`: если передан `em` (уже в транзакции) — advisory lock и сид в нём; иначе
  как сейчас (своя транзакция на форке). `POST /households/:hid/categories/seed-defaults` не меняется.
- `createHousehold` и регистрация: бюджет, owner и категории — в **одной** транзакции. Ошибка сида откатывает всё
  (для регистрации — и пользователя); блок `try/catch` с логом в регистрации убирается.

### Лимит бюджетов

- `household-limits.env.ts`: `HOUSEHOLD_MAX_HOUSEHOLDS`, целое ≥ 1, по умолчанию 5; DI-токен как у
  `MAX_ACTIVE_INVITES`; добавить в `.env.example`.
- Считаются членства пользователя в бюджетах с `deleted_at IS NULL` (любая роль).
- Проверка: в `createHousehold` и в `acceptInvite` (после проверок приглашения, до вставки участника), в
  транзакции под `pg_advisory_xact_lock(hashtext('household-count:' || userId))`. `≥ лимита` → 409 с
  `reason: 'household_limit'`.
- Регистрация лимит не проверяет (бюджет первый).

### Удаление

- 403 — не owner (как сейчас).
- В транзакции под тем же advisory lock на пользователя-owner:
  - в бюджете есть участники кроме owner → 409 `reason: 'household_has_members'` (снимает HAN-145);
  - это последний живой бюджет owner (по членствам) → 409 `reason: 'last_household'`;
  - иначе `deleted_at = now()`.
- Членства и приглашения не трогаем: удалённый бюджет отсекает `findHouseholdRole`, приглашение отвечает 410
  `household_deleted`.

### Своё имя

- Миграция: `household_members.display_name varchar(255) null`.
- `PUT /households/:hid/me { display_name: string | null }` — любой участник (`HouseholdMemberGuard`), только своя
  строка. Строка тримится; пустая после трима → 400; `null` сбрасывает к основному имени. Ответ —
  `HouseholdResponseDto`.
- `PUT /households/:hid` по-прежнему меняет основное имя, только owner.
- В `HouseholdResponseDto`: `name` = `display_name ?? households.name` для текущего пользователя;
  новое поле `original_name` = `households.name`. Так в списке, карточке, создании и обновлении.
- `getHousehold` и `updateHousehold` получают `userId`, чтобы взять имя текущего пользователя.

### Список

- `GET /households`: один SQL — членства пользователя в живых бюджетах + `member_count` и `bill_count`
  подзапросами/`GROUP BY`; сортировка `households.created_at asc, id asc`.
- `bill_count` — чеки с `deleted_at IS NULL` и `status IN ('confirmed', 'draft')`.
- `bill_count` только в списке; в карточке и других ответах — не нужен (фронт берёт из списка).

### Swagger

Описания операций и полей: `original_name`, `bill_count`, коды 409 с `reason`, новый `PUT :hid/me`.

## Тесты

- e2e: созданный бюджет имеет категории по умолчанию; валюта переданная / пользователя.
- e2e: 6-й бюджет → 409; принятие приглашения при 5 бюджетах → 409; после удаления одного можно снова создать.
- e2e: удаление последнего → 409; не-owner → 403; бюджет с другим участником → 409; обычное удаление → 204 и бюджет
  пропал из списка.
- e2e: `display_name` — участник задаёт, видит в списке и карточке, owner видит основное; `null` сбрасывает;
  пустая строка → 400; `original_name` у всех одинаковое.
- e2e: `bill_count` считает confirmed + draft, без failed/duplicate/удалённых; `member_count` верный.
- int: регистрация при падении сида откатывается целиком (нет пользователя); параллельные создания не обходят
  лимит; параллельное удаление двух последних бюджетов оставляет один.
- unit: парсер `HOUSEHOLD_MAX_HOUSEHOLDS`.

## Оставлено исполнителю

- Точная форма SQL списка (подзапросы или `GROUP BY`), если она укладывается в один запрос.
- Какой `em` получает сид в регистрации — `txEm` из её текущей транзакции.
- Тексты сообщений 409.

## Влияние на фронт (HAN-26)

- `name` теперь «моё имя бюджета», `original_name` — основное; поле «своё имя» для участника, `PUT :hid/me`.
- 409 `last_household` / `household_has_members` / `household_limit` — понятные тексты.
- `bill_count` для подтверждения удаления; список отсортирован, первый — бюджет по умолчанию.
